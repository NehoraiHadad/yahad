# גבולות המערכת והאבטחה

## בחירות בסיס

שרת Node 24 אחד מגיש React שנבנה מראש, API ומסלול SSE, ומחזיק Connector אחד לכל משפחה מקושרת. SQLite מקומי ב־WAL מתאים לנקודת הפתיחה; מאגר הנתונים ופעולות הסינון מרוכזים ב־Store/ChatService. יש נעילת תהליך ל־DATA_DIR, ולא מנסים להריץ מספר כותבים על אותה התקנה. פיצול עתידי דורש החלפת fan-out בזיכרון, lease לחיבור משפחתי ושכבת אחסון; חוזה המתאם אינו תלוי ב־Fastify או ב־React.

| ישות | גבול |
| --- | --- |
| families | מזהה UUID שנוצר מקומית; כמה משפחות באותו DB |
| users | FK משפחתי, role parent/child, name יחיד לתצוגה ולכניסה, name_key פנימי גלובלי ייחודי וסיסמה מומלחת |
| grants | family + child user + stable group JID |
| groups | family + JID; רק כותרת ניהולית מינימלית נשמרת, מוצפנת |
| group_keys | family + JID; מפתח תוכן אקראי עטוף במפתח השרת |
| messages/media | מפתח מורכב family + group + ID, עם FK; מזהה אינו הרשאה |
| auth | family + Signal key identifier; ערכים מוצפנים ב־AES-GCM |
| identity_labels | family + child; חתימה שהורה בוחר, מוצפנת ב־AES-GCM |
| sessions | token אקראי; רק SHA-256 של token נשמר, יחד עם family/user/תפוגה/CSRF |
| family_connections | מצב תפעולי אחרון בלבד; QR נשמר בזיכרון בלבד |

אין שאילתת תוכן/הרשאות שנשענת על ״המשפחה הראשונה״. חיפוש משתמש לצורך login נעשה לפי name_key מנורמל וייחודי, הנגזר מהשם היחיד, לפני שיש סשן. ניקוי סשנים, גיבוי וניקוי קבצים יתומים הם פעולות ניהול התקנה ולכן סוקרות יותר ממשפחה אחת. ממשק ההורה תמיד מוגבל למשפחתו.

## זרימת מידע

1. הספרייה עשויה לקבל ולפענח מידע מכל חשבון ההורה. זו מגבלה מהותית של linked device, ואינה נפתרת על ידי הסתרה בממשק.
2. המתאם בודק group JID יציב ואת קיום grant משפחתי לפני נרמול/קליטה. הודעות פרטיות וקבוצות לא מאושרות אינן נכנסות ל־Store. רשימת הקבוצות להורה שומרת רק JID וכותרת, בלי תיאור קבוצה, משתתפים או הודעה אחרונה.
3. קליטת תוכן בודקת שוב הרשאה לפני הורדת מדיה ולפני שמירה; מזהה מפתח קבוצה מונע מהורדה שהתחילה לפני מחיקה להחיות תוכן אחרי ביטול ואישור מחדש.
4. ציטוטים אינם מועתקים מה־wire: נשמר לכל היותר מזהה הודעה שנמצאת **באותה קבוצה ונשמרה באישור**. טקסט/תמונה מצוטטים, externalAdReply, הקשרים מוטמעים ותצוגות מקדימות נמחקים גם מה־raw המוצפן. סוגי הודעות לא נתמכים אינם שומרים raw. תוכן זמני/חד־פעמי אינו נשמר כתוכן רגיל.
5. טקסט ו־wire retriable מוצפנים במפתח הקבוצה. מדיה נשמרת בקובץ בשם hash של family/group/media ID; התוכן מוצפן במפתח הקבוצה עם AAD שמכיל את ההקשר. הנתיב הפיזי אינו מוחזר לדפדפן.
6. SSE משדר invalidation בלבד. לכל חיבור סשן משפחתי, ולכל אירוע בדיקת family/group מחודשת. אין payload של תוכן, QR או רשימת קבוצות לא מאושרות. הדפדפן טוען נתונים מחדש מ־API מאומת.
7. כל קובץ נטען דרך מסלול family/session/group מאומת. `Cache-Control: no-store`, בלי public URLs או signed URLs שימשיכו לעבוד אחרי ביטול. PDF/HTML ומסמכים תמיד attachment/octet-stream, ותוכן inline מוגבל לסוגים שזוהו בבייטים. Range מאומת באותו מסלול כדי לתמוך במדיה בדפדפנים.

## שליחה וזהות

היעד מגיע מנתיב ה־API ונבדק לפי סשן ו־grant. אין API להעברה לכתובת שרירותית ואין קבלת URL חיצוני להעלאה. reply/edit/delete/reaction/read/history מאמתים את ההודעה באותה family/group. ילד יכול לערוך/למחוק רק הודעות שהאפליקציה שייכה לו; הודעות שההורה שלח מהטלפון אינן מקבלות שיוך כזה. הורה יכול לנהל הודעות עצמיות בקבוצות שאושרו במשפחתו.

חתימה היא פעולה בשרת; לקוח ששינה בקשת HTTP לא יכול להסיר אותה. החתימה נשמרת גם בנתוני ההודעה לשימוש בעריכות. שינוי החתימה אינו משנה הודעות ישנות. קול ומדבקות נשלחים אחרי הודעת זיהוי נפרדת, כי אין להם caption מתאים; שני משלוחים אינם אטומיים, וייתכן שהזיהוי יישאר ללא המדיה אם הפעולה השנייה נכשלה. זהות ה־WhatsApp בכל מקרה נשארת ההורה. תגובות emoji אינן ניתנות לחתימה.

לשליחה מזהה client UUID שהופך למזהה wire יציב; לחיצה חוזרת באותו מזהה לא יוצרת אוטומטית הודעה חדשה במאגר. כשל תקשורת יכול להיות עמום: ייתכן שההודעה הגיעה למרות שאין אישור. אין הבטחת exactly-once מול WhatsApp; retry מחייב אישור מתוך הממשק ומשתמש באותו מזהה כשאפשר. שליחה שכבר הועברה ל־WhatsApp בזמן ביטול הרשאה אינה ניתנת לביטול רטרואקטיבי; הבקשה נבדקת שוב אחרי כל עיבוד מקדים ולפני המשלוח הבא.

## מחיקה וביטול גישה

ביטול grant מונע בקשות חדשות מיד ומשגר invalidation לכל דפדפני המשפחה. כשאין עוד ילד מורשה באותה קבוצה, נמחקים ההודעות, המדיה ומפתח הקבוצה מהמאגר הפעיל. אם יש ילד אחר מורשה במשפחה, העותק נשאר עבורו והילד שהוסר נדחה בשרת. WAL עובר checkpoint/truncate אחרי המחיקה. נשארת להורה רק רשומת JID/כותרת בבורר.

ניתוק יכול לשמור שיחות מאושרות לקריאה או למחוק אותן. בשני המצבים נעצר המתאם ונמחק auth פעיל. אם logout מרוחק נכשל בזמן ניתוק רשת, המפתחות המקומיים עדיין נמחקים; ההורה צריך לבדוק ברשימת מכשירים מקושרים בטלפון במקרה הצורך. מחיקת משפחה דורשת סיסמת הורה, מוחקת גם משתמשים/sessions/grants והעדפות, ואינה נוגעת במשפחות אחרות.

אין הבטחה למחיקת הורדות מדפדפן/גלריה, צילום מסך או עותק גיבוי חיצוני. גיבויים מוצפנים פגים במדיניות 7 ימים. שחזור ישן מחייב החלה מחדש של מחיקות והרשאות שבוטלו מאז הגיבוי.

## אימות והקשחה

- סיסמאות 14–256 תווים עם scrypt, salt אקראי והשוואה timing-safe. login ללא משתמש מבצע גם הוא scrypt. עד 3 פעולות login יקרות במקביל, עם rate limit לפי IP ומפתח השם המנורמל.
- סשנים אקראיים, HttpOnly, SameSite Strict ו־Secure ב־HTTPS; תפוגה מוחלטת עד 12 שעות כברירת מחדל, וגם 15 דקות חוסר פעילות לילדה. זרם SSE ו־GET אינם מאריכים session idle. פעילות דורשת POST מאומת.
- CSRF אקראי לכל סשן, בדיקת Origin מדויקת לכל mutation; CORS אינו פתוח. חסימת framing בשרת השוטף, CSP, no-referrer, nosniff והגבלת microphone ל־self.
- נעילה מקומית/ביטול UI בכל טאבי הדפדפן. במצב offline אי אפשר לבטל סשן שרת מיידית, אך התצוגה המקומית ננעלת ונמנעת כניסה אוטומטית עד הזדהות נוספת. משתמש בעל גישה פיזית מלאה לכלי הפיתוח של דפדפן משותף אינו גבול אבטחה של מערכת הפעלה; מומלץ לנעול גם את הטאבלט.
- עד 2 העלאות במקביל בהתקנה, עד 16 MiB לקובץ כברירת מחדל, 30 פעולות שליחה לדקה למשתמש, ועד 64 זרמי SSE. תור קליטה מוגבל ל־512 הודעות; עומס עלול לגרום לחורים וההיסטוריה נשארת מסומנת כחלקית.
- מגבלת מדיה פעילה 2 GiB למשפחה כברירת מחדל. אין כרגע מחיקה אוטומטית של טקסטים לפי גיל; יש לעקוב אחרי מקום פנוי. אין הבטחה לקיבולת עד בדיקה במכשיר האמיתי.
- ffmpeg מקבל קלט דרך pipe עם פרוטוקולי קלט מוגבלים, הגבלת זמן/פלט וללא קובץ קול מפוענח זמני. נוצר thumbnail אמיתי בזיכרון למתאם Baileys; הוא מקבל duration שנמדד מהקול כדי לא להפעיל יצירת קובץ original גלוי בתוך הספרייה. Baileys עדיין עשוי ליצור קובץ העלאה מוצפן זמני. systemd משתמש ב־PrivateTmp.
- כתובות מדיה של WhatsApp נבדקות ל־HTTPS תחת whatsapp.net ולנתיב תקין לפני בקשת רשת. אין fetch לתצוגות מקדימות של קישורים. אין סריקת אנטי־וירוס למסמכים; הדפדפן מוריד אותם כקבצים, ועל המכשיר הפותח להחיל את הגנותיו.
- לוגי HTTP ו־Baileys כבויים. הודעות console גולמיות של תלות Signal מבוטלות ב־main, מפני שחלק מהתלות יכול להדפיס session רגיש. שגיאות לא צפויות מדפיסות רק טקסט תפעולי קבוע. אין לוג של passwords/QR/content/cookies. core dumps כבויים ב־systemd.

אין ״ניהול משתמשים כללי״, הרשאות דינמיות, טלמטריית ילד, billing או מערכת ניטור. לפני הפיכת המערכת למוצר רב־משפחתי מסחרי נדרשים ביקורת חיצונית, אימות פרוטוקול בפועל, עדכון תלויות, מדיניות נתונים ומסלול חיבור רשמי/מאושר; בידוד המתאם אינו פותר את שאלת הלגיטימיות או התאימות של פרוטוקול WhatsApp.
