# גיבוי ושחזור שניתן לבדוק

## מה כלול והיכן הסיכון

ארכיון כולל SQLite, קבצי מדיה מוצפנים ואת מפתח האפליקציה בתוך ההצפנה. בתוך SQLite נמצאים גם אישורי WhatsApp ו־Signal המוצפנים. מי שמחזיק את הארכיון ואת סיסמת הגיבוי יכול לשחזר את החשבון המקושר. נותנים גישה רק למפעיל המשפחה, ושומרים סיסמת גיבוי נפרדת במנהל סיסמאות מקומי. אין למסור אותה בצ׳אט.

הארכיון מוצפן ב־AES-256-GCM, עם salt ו־nonce אקראיים, ומפתח scrypt ‏N=32768,r=8,p=1. כותרת הפורמט מאומתת כ־AAD. אין קובץ tar גלוי בדרך. המימוש מזרים קבצים, ואינו טוען את כל הארכיון לזיכרון. הנתונים הפעילים ממשיכים להיות מוצפנים גם בזמן האריזה.

## יצירה

1. עוצרים את השירות. גיבוי תופס את אותו lock כמו השרת ומסרב לעבוד על נתונים בשימוש.
2. טוענים את תצורת DATA_DIR ו־MASTER_KEY_FILE של אותה התקנה דרך קובץ הסביבה המקומי; אין להדפיס את המפתח.
3. מריצים:

```bash
npm run backup -- create /private/backup-directory
```

הכלי מבקש סיסמה באורך 18 תווים לפחות, ללא הדפסה על TTY. בסיום מוחזר נתיב הארכיון. התיקייה נוצרת עם `0700`, והארכיון עם `0600`. ב־Pi ניתן להשתמש ב־`scripts/backup-daily.sh` לאחר סקירה: הוא עוצר systemd, מבצע גיבוי ומחזיר את השירות גם אחרי שגיאה.

## שמירה ומחיקה

- לכל היותר 7 עותקים, ושום עותק ישן מ־7 ימים בתיקייה המנוהלת. יצירת גיבוי מבצעת אכיפה מיידית.
- מצורפים `deploy/yachad-backup-expiry.service` ו־`.timer` למחיקה יומית ללא צורך בסיסמה, כדי שגם הפסקת גיבויים לא תשאיר ארכיונים ישנים ללא הגבלה. timer זה **אינו יוצר גיבוי**.
- גיבוי ידני שוטף: יומי, או אחרי שינוי הרשאות/תצורה. בלי מנגנון מפתח מקומי נוסף שהמפעיל בחר, סיסמת הגיבוי מוזנת ידנית. אין שמירת passphrase ב־systemd או בסקריפט.
- עותק ידני בדיסק אחר צריך הצפנה, הרשאות ותפוגה זהות. הכלי אינו מסוגל למחוק עותקים חיצוניים שאינם בשליטתו.
- מחיקת קבוצה מוחקת את המדיה וההודעות ואת מפתח הקבוצה הפעיל. היא אינה יכולה למחוק תמונות שכבר הורדו למכשיר או עותקים בארכיונים ישנים. אלה פגים במדיניות שלעיל. מחיקת קובץ אינה הבטחת מחיקה פיזית מכל תא flash או יומן של מערכת הקבצים.

## שחזור

היעד חייב להיות ספרייה **שאינה קיימת**. כל הארכיון מאומת לפני יצירת קובץ פלט; סיסמה שגויה או שינוי בבית בודד מפילים את השחזור. מאחר שהארכיון מאומת גם במעבר הפענוח לכתיבה, יש לשמור את קובץ הגיבוי read-only בזמן שחזור.

```bash
npm run backup -- restore /private/backups/ACTUAL_FILE.backup /private/restore-NEW
```

השחזור כותב `app.sqlite`, ‏`media/` ו־`master.key` עם הרשאות מוגבלות, מסנן שמות קבצים, מסרב לדריסות ולנתיבי traversal ובודק `integrity_check` ו־`foreign_key_check`. כל סשני הדפדפן נמחקים. ה־master.key החדש צריך לעבור למקום הסודות המוגן של ההתקנה עם הבעלות המתאימה; עדכון DATA_DIR ו־MASTER_KEY_FILE חייב להצביע לאותו שחזור.

לפני פתיחת גישה לטאבלט: מתחילים כשהגישה לרשת הביתית חסומה או כשהשירות עצור; בודקים שה־connector וסביבת השחזור תואמים למקור, שהמשתמשים נכונים, ושאין הרשאות שבוטלו מאז מועד הגיבוי. יש להחיל מחדש כל ביטול הרשאה/מחיקה שהתרחשו אחרי הגיבוי. אין להפעיל auth משוחזר מול חשבון אמיתי במקביל לשרת המקורי.

הגיבוי אינו כולל את קוד המקור, תצורת systemd/Caddy, CA TLS או קובץ env. הקוד נמסר בנפרד; מכינים מחדש env מנתיבי השחזור והקונפיגורציה הרצויה. גיבוי של מאגר Baileys חייב להישאר במצב Baileys; אין לפתוח אותו כ־mock כדי ״לבדוק״ ללא חיבור. בדיקות offline משתמשות בשכבת Store או במתאם בדיקה מוזרק, כפי שמודגם בטסטים.

## מה נבדק בפועל

בדיקת האינטגרציה יוצרת משפחה ומשתמשים, הודעה, מדיה, auth לדוגמה וסשן; יוצרת גיבוי מוצפן; דוחה סיסמה שגויה וארכיון ששונה; משחזרת לספרייה חדשה; מאמתת התאמה של בייטי המדיה, תוכן ההודעה ו־auth; ומוודאת שאין סשן משוחזר. נבדקות גם הרשאות קובץ, נעילת נתונים ואכיפת 7 עותקים/7 ימים.

זהו אימות אמיתי של כלי הגיבוי והשחזור על שרת הפיתוח, עם **אישורי דוגמה**. שחזור חיבור WhatsApp חי, הפעלה לאחר reboot ו־systemd על Pi עדיין לא נבדקו.

## גיבוי לפני עדכון אוטומטי

שירות העדכון משתמש באותו פורמט מוצפן ואותה מדיניות שמירה, עם סיסמה אקראית מקומית ב־root600. היא מועברת ב־stdin לתהליך גיבוי לא מיוחס בזמן שהאפליקציה עצורה. שומרים אותה מחוץ ל־Pi לשחזור; אין מפתח קבוע בקוד. קובצי diagnostics אינם נכללים בגיבוי, משום שהם סיכומים תפעוליים מתכלים. ההגדרות של updater ו־Caddy אינן חלק מגיבוי האפליקציה. ראו [UPDATES.md](UPDATES.md).
