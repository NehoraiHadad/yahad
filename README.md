# יחד — Yachad

History ingestion/request fixes are documented in [HISTORY.md](docs/HISTORY.md). Automatic-update activation remains an owner step.

For the 0.3.2 candidate see [GitHub HTTPS automatic updates and one-time owner setup](docs/GITHUB-UPDATES-SETUP.md) and [parent UI control](docs/UI-UPDATE-CONTROL.md). The new owner profile needs no signing key or GitHub token; existing signed installations retain their trust policy. Preserve live data/key paths. A GitHub push does not deploy the Pi.


מערכת צ׳אט משפחתית אמיתית, בהרצה מקומית: Node.js 24 + Fastify + React + SQLite. אותו תהליך מגיש את הממשקים, מחזיק סשנים ומפעיל מתאם WhatsApp מתמשך. אין שירות ענן או מנוי נדרש. ברירת המחדל היא מתאם מדומה עם נתונים מקומיים. מתאם Baileys אמיתי נמצא באותו מקור, נעול לגרסה `7.0.0-rc14`, ומוגן באישור מקומי מפורש.

זו גרסה ראשונה עובדת לבדיקה משפחתית. היא **אינה חיבור WhatsApp רשמי ואינה מוצר שעבר ביקורת אבטחה חיצונית**. חיבור אמיתי ופריסה פיזית טרם נבדקו. תוצאות מדויקות: [docs/VALIDATION.md](docs/VALIDATION.md).

להתקנה הראשונה על Pi 4 עם Debian13/ARM64: **[מדריך התקנה צעד־אחר־צעד](docs/PI-QUICKSTART.md)**.

## הפעלה מקומית קצרה

דרישות: Node.js 24.x, npm, ו־ffmpeg זמין ב־PATH. SQLite כלול ב־Node; אין שרת מסד נתונים להתקין. התקנה ראשונית של חבילות דורשת רשת; ממשק המשתמש עצמו אינו טוען גופנים, תמונות או סקריפטים משירות חיצוני.

```bash
npm ci
npm run setup
npm run build
npm start
```

`setup` מבקש מקומית שם משפחה פנימי, שני שמות משתמש שונים ושתי סיסמאות נפרדות באורך 14 תווים לפחות. הסיסמאות אינן מוצגות ואינן נשמרות בקובץ התצורה. נוצר מפתח אקראי בקובץ מקומי עם הרשאות `0600`. אין סיסמת ברירת מחדל. גולשים ל־`http://localhost:3000` **במחשב שעליו רץ השרת**, נכנסים כהורה, מפעילים את המתאם המדומה ובוחרים קבוצות. מהטאבלט בבית יש להשתמש ב־HTTPS כמפורט בהמשך.

אפשר ליצור עוד משפחה באותה התקנה על ידי עצירת השירות והרצת `npm run setup` שוב, עם שמות משתמש ייחודיים. שום משפחה או מזהה משתמש לא קבועים בקוד. אין כרגע הרשמה ציבורית או ממשק SaaS לניהול משפחות.

### דוגמאות עשירות לבדיקות

להכנת נתונים מדומים עם שלוש קבוצות מאושרות, על ספריית נתונים ריקה בלבד:

```bash
read -rs -p 'Local demo parent password: ' DEMO_PARENT_PASSWORD; printf '\n'
read -rs -p 'Local demo child password: ' DEMO_CHILD_PASSWORD; printf '\n'
export DEMO_PARENT_PASSWORD DEMO_CHILD_PASSWORD
npm run demo
unset DEMO_PARENT_PASSWORD DEMO_CHILD_PASSWORD
npm run build
npm start
```

יש לבחור שתי סיסמאות שונות באורך 14 תווים לפחות. שמות המשתמש בדוגמאות הם `parent` ו־`child`; הסיסמאות הן אלו שהזנתם מקומית. הדוגמאות כוללות תמונה, סרטון קצר, PDF, מדבקה וקובץ קול של **צליל בדיקה**, לא דיבור של אדם. שיחות וסטטוסים מדומים מסומנים במפורש בממשק.

`npm run dev` הוא **שרת QA נפרד עם משפחה סינתטית שנמחקת בכל הפעלה וכניסות בדיקה אוטומטיות**. אין להשתמש בו בבית או בענן. הוא מסרב למצב production ול־Baileys. הוא אינו מסלול ההפעלה השוטף; לשירות האמיתי משתמשים ב־`npm start`. מידות בדיקה: `/__qa/frame/tablet` ו־`/__qa/frame/mobile`; `?role=parent` פותח ממשק הורה בסביבת הבדיקה בלבד. מסלולים אלה אינם קיימים בשרת `npm start`.

## מה עובד

- אימות נפרד להורה ולילדה, סיסמאות scrypt עם salt, עוגיות HttpOnly / SameSite=Strict, סשנים בעלי תפוגה, CSRF, בדיקת Origin והגבלת ניסיונות כניסה.
- בחירת קבוצות לפי JID יציב, לפי משפחה וחשבון ילד; כל API, מדיה, חיפוש, שליחה ואירוע נבדקים בשרת. ההורה יכול לפתוח רק שיחות קבוצתיות שהמשפחה אישרה לילדים.
- שליחה, קבלה ושינויי שיחה בזמן אמת, עימוד מקומי של היסטוריה ובקשת היסטוריה מ־WhatsApp כשהמתאם תומך. תמיד מוצג שהיסטוריה עשויה להיות חלקית.
- מענה בטוח להודעה קיימת מאותה קבוצה, אימוג׳ים ותגובות, תמונות, MP4, מסמכים, מדבקות WebP, הקלטת קול עד שתי דקות והשמעה. חיפוש מוגבל ל־2,000 ההודעות האחרונות שנשמרו בקבוצה, עד 40 תוצאות.
- עריכת הודעת טקסט שנשלחה מהאפליקציה בחלון 15 דקות, מחיקה לכולם, נוכחות הקלדה וסימוני מסירה/קריאה שמקורם במתאם. במצב אמיתי אין יצירה של ״נמסר/נקרא״ באמצעות טיימר.
- חתימה אופציונלית שההורה מגדיר; השרת מצרף אותה לטקסט ולכיתובי מדיה. קול ומדבקות מקבלים הודעת זיהוי נפרדת לפניהם. כשאין מענה אחר, המדיה נשלחת גם כמענה להודעת הזיהוי. זו **חתימה בטקסט, לא זהות WhatsApp נפרדת ולא הוכחת זהות**. תגובות אימוג׳י עדיין שייכות להורה. אם המדיה נכשלת, הודעת הזיהוי עלולה להישאר לבדה.
- ממשק RTL, התאמה לטאבלט ולנייד, ערכות מרווה/לילך/אפרסק, רקעים ומצב כהה. אין התראות דחיפה, פרסומות, ניקוד או רצפי שימוש. אין שמירה מקומית של תוכן שיחות ב־localStorage; נשמרות רק העדפות מראה ומצב נעילה.
- נעילה ויציאה ידנית, נעילת חוסר פעילות לילדה אחרי 15 דקות כברירת מחדל, שינוי סיסמאות, ניתוק חשבון, מחיקת שיחות או מחיקת משפחה. נעילה מקומית פועלת גם אם השרת מנותק; ביטול הסשן בשרת דורש תקשורת, או מתבצע בתפוגת חוסר הפעילות.

## פריסה על ה־Pi — רק לאחר גישה ואישור

הוראות מפורטות: [docs/PI.md](docs/PI.md). **התקנת האפליקציה על Pi טרם בוצעה.** המשתמש שלח פלט המאשר Pi4/כ־4GB/ARM64/Debian13 ו־21GB פנויים. במכשיר חדש מריצים קודם בדיקה לקריאה בלבד:

```bash
bash scripts/inspect-host.sh
```

הסקריפט מציג דגם בפועל אם זמין, זיכרון, ארכיטקטורה, מערכת הפעלה, דיסק ו־runtime. אין להמשיך בהתקנה לפני בדיקת התוצאות. ההוראות המוכנות מכוונות ל־Linux ‏64-bit עם systemd ו־Node 24 נתמך. אם מתגלה מערכת 32-bit או מערכת לא נתמכת, עוצרים ומתאימים הוראות; אין להחליף מערכת הפעלה או למחוק כרטיס זיכרון אוטומטית.

הפריסה המתועדת: קוד ב־`/opt/yachad/current`, נתונים מתמשכים ב־`/var/lib/yachad`, מפתח ותצורה ב־`/etc/yachad`, משתמש שירות לא מיוחס, ו־systemd עם הפעלה באתחול והתאוששות מקריסה. Node מאזין ל־loopback בלבד. Caddy, כתהליך TLS קטן נוסף, מאזין **לכתובת LAN פרטית אחת בלבד** עם CA מקומי. אין פתיחת פורטים בראוטר, UPnP, מנהרה או חשיפה לאינטרנט.

## HTTPS והקלטה בטאבלט

כתובת `http://192.168...` אינה מאפשרת מיקרופון. הגדרת Caddy מצורפת ב־`deploy/Caddyfile`, עם `tls internal`; יש להתקין בטאבלט את **התעודה הציבורית של ה־CA** ולוודא שהדפדפן סומך עליה. אין להעביר אליו את המפתח הפרטי של ה־CA או את מפתחות WhatsApp. שם/IP, כתובת APP_ORIGIN והתעודה חייבים להתאים. הוראות ואימות: [docs/PI.md](docs/PI.md#tls-מקומי-וטאבלט).

## חיבור WhatsApp אמיתי — באישור נפרד בלבד

לא בוצע קישור אמיתי. לאחר קבלת אישור, רצוי עם מספר ניסוי, מכינים ספריית נתונים ומפתח **נפרדים מנתוני הדוגמה**, מריצים setup ומגדירים:

```dotenv
CONNECTOR=baileys
ALLOW_REAL_WHATSAPP=I_APPROVE_UNOFFICIAL_LINK
APP_ORIGIN=https://YOUR_PRIVATE_LAN_IP
COOKIE_SECURE=true
```

מפעילים מחדש, נכנסים כהורה, בוחרים ״קישור החשבון״ וסורקים את ה־QR מתוך WhatsApp בטלפון ההורה. לאחר חיבור, רשימת הקבוצות מתעדכנת; רק קבוצות שאושרו נגישות לילדה. אין בקשה לסודות בצ׳אט. מאגר נתונים שהוכן במצב mock מסרב להיפתח במצב baileys כדי שלא להציג דוגמאות כאילו היו היסטוריה אמיתית.

השרת הוא מכשיר מקושר של ההורה. הוא עשוי לקבל ולפענח בזיכרון גם מידע שאינו מאושר; האפליקציה מסננת לפני שמירה, הורדת מדיה ופרסום אירועים. אין פרטיות מההורה ואין הבטחה להצפנה מקצה לקצה עד הדפדפן. חשבון ההורה נשאר זהות השולח.

חיבור לא רשמי עלול להישבר או לגרום להגבלת החשבון. חידוש אוטומטי נעשה רק לניתוקים שניתן לשחזר; ביטול הקישור, session פגום או איסור מחייבים התערבות/QR. החלפת החיבור על ידי מכשיר אחר מוצגת בנפרד. WhatsApp עשוי לנתק מכשירים מקושרים אם הטלפון הראשי לא בשימוש 14 יום. אין הבטחת השלמת הודעות מזמן ניתוק.

## גיבוי ושחזור

מדריך מלא ובדוק: [docs/BACKUP.md](docs/BACKUP.md). הגיבוי כולל SQLite, מדיה מוצפנת ואישורי WhatsApp, ומכיל את מפתח האפליקציה **בתוך מעטפת מוצפנת**. הוא מוגן ב־AES-256-GCM עם מפתח נגזר ב־scrypt מסיסמת גיבוי נפרדת. אין גיבוי גלוי. ברירת השמירה: עד שבעה גיבויים ועד שבעה ימים; מצורף timer לאכיפת תפוגה גם בלי גיבוי חדש. עותקים ידניים/חיצוניים מחייבים את אותה מדיניות.

```bash
# יש לעצור קודם את השירות; שני התהליכים משתמשים באותו lock.
npm run backup -- create /private/backup-directory
npm run backup -- restore /private/backup-directory/ACTUAL_FILE.backup /private/new-restore-directory
```

סיסמת הגיבוי מוקלדת מקומית ללא הדפסה. השחזור מאמת את **כל** הארכיון לפני כתיבה, מסרב לדריסת ספרייה קיימת, בודק תקינות SQLite ומבטל את כל סשני הדפדפן. מחיקה מהמערכת הפעילה אינה מוחקת אוטומטית עותקים ישנים: הם פגים לפי מדיניות השמירה. שחזור מחזיר את מצב ההרשאות בזמן הגיבוי; יש לבדוק ולהסיר הרשאות שבוטלו מאז לפני חיבור לילדה או ל־WhatsApp.

## 0.3.3 — בקרת עדכונים ברורה

מצב העדכונים הפעיל מוצג בנפרד מכפתור השינוי, והמעבר בין אוטומטי להודעה בלבד דורש אישור ברור. בקשה ממתינה אינה מוצגת כשינוי שהוחל. ההגדרה הקיימת של רכיב העדכון נשמרת; פרטי האמון הנוכחיים במדריך [GitHub updates](docs/GITHUB-UPDATES-SETUP.md).

תיקון הרשאת הכתיבה לשינוי מצב דורש הגדרה מקומית של שירות השורש, ואינו מותקן בהפצת האפליקציה. ראו [תיקון בקרת המצב](docs/UPDATE-MODE-REPAIR.md). בקשת מצב ממתינה עלולה לעכב גם בדיקת גרסאות; פרסום Release אינו הוכחה שהמכשיר קיבל אותו.
